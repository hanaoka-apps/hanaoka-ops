① 全体の流れ

Shopify に入った注文を、人が確認して、SMILE に取り込むデータ（納品先・受注伝票）にするアプリです。注文の取得と、SMILE への取込は、自動で動きます。人がやるのは、内容の確認と「OK」です。

Shopifyお客様の注文・入金
→
専用機が取得平日8〜18時の毎時0分
→
この画面が自動で読む注文が一覧に並ぶ
→
人が確認して OK見比べて、直す・外す
→
「SMILEに取り込む」取込ボタン（管理者）
→
専用機が SMILE に取込→ 確認用に出力
→
画面が突き合わせ一致で「確認待ち」
→
確認OK「起票済み」
自動人が操作

② どこまでが自動で、どこからが人の仕事か

自動でやってくれること人がやること
  • Shopify の注文・入金の取得：専用機が Shopify の API から、平日の8時〜18時の毎時0分に取ります（1回約20秒）。直近55日ぶんです
  • 画面への読み込み：取得したファイルを、この画面が自動で読みます（CSV を手で入れる必要はありません）
  • SMILE の最新の状態の読み込み：専用機が SMILE から出力したファイルを読み、すでに SMILE にある注文を見分けます
  • 品目への変換・出荷予定日・休業日の判定・文字の確認：「対応表」と決まりごとに従って、自動で計算します
  • SMILE への取込と、取込結果の突き合わせ（専用機と画面が自動で行います）
  • 注文の内容を見て、おかしくなければ OK
  • 黄色や赤の確認事項を見て、出荷予定日・社内メモを直す、または「対象外」にする
  • 「SMILEに取り込む」を押す（管理者のみ）
  • 取込のあとの 確認OK（管理者のみ）
  • 「要確認」になった注文を SMILE で見て判断する
Shopify の管理画面から CSV をダウンロードして画面に入れる方法も残してあります（自動の取得が止まったとき・急いで最新にしたいとき）。入れたCSVが自動のものより優先されます。

③ データの新しさ

画面の上の緑の帯に、いつの時点のデータかが出ています。

表示意味
Shopify注文 105件／Shopify取得：5分前専用機が最後に Shopify から取った時刻です。毎時0分ごとに更新されます。36時間以上古いと「自動取得が止まっている可能性」と警告が出ます（専用機のタスクを確認します）
SMILEの最新データ：1時間前SMILE の受注・納品先を最後に出力した時刻です。「すでに SMILE に入っている注文」の判定に使います。古いと、取込の前に二重取込の確認が古い可能性があります
右上の ↻ 更新画面が、最新のファイルを読み直します（Shopify・SMILE のファイルを自分で取りに行くわけではありません）
右上の SMILEの最新を取り込む（約3分）管理者用。専用機に「SMILE から今すぐ最新を出力して」と頼みます。取込の前に押すと、二重取込の確認が最新になります
Shopify から取るのは直近55日です。それより古い注文は、画面に出なくなります（履歴には、操作の記録が残ります）。

④ 注文の状態の見方

上の絞り込みのボタンが、状態ごとの件数です。

状態意味次にすること
未確認Shopify から読んだだけ。まだ誰も見ていない内容を見て、OK または 対象外
OK済（取込待ち）OK した。SMILE に取り込む順番を待っている「SMILEに取り込む」（管理者）。やめるときは「戻す」
取込中・突合待ち専用機が SMILE に取り込んでいる、または取り込んだ結果を突き合わせている待つ（数分）
確認待ちSMILE の値が、アプリの期待どおりだった。受注№が付く確認OK（管理者）で「起票済み」
要確認SMILE の値が、期待と違う／結果が分からない。勝手に再取込はしませんSMILE で伝票を見て判断（管理者）。取り込まれていなければ「未確認に戻す」
起票済SMILE に取り込み、確認も済んだなし
SMILE取込済SMILE に、同じ注文番号の伝票がすでにある（アプリを使う前に手で入れたものを含む）なし。二重取込にならないよう、取込の対象にはなりません
対象外キャンセル済み・決済の取消は自動で。そのほかは、人が理由をつけて外したもの外したものは「未確認に戻す」で戻せます

⑤ 使い方（日々の流れ）

  1. 画面を開く：上の緑の帯で、Shopify の取得が新しいかを見ます。
  2. 一覧を見る：「未確認」を選ぶと、まだ見ていない注文が並びます。注文日で絞る（「注文日 ○○以降」）、注文番号・お客様名で探すこともできます。
  3. 注文をクリック：右に詳細が開きます（⑥）。Shopify と SMILE に入る内容を左右で見比べます。
  4. OK にする：問題なければ「OK」。一覧で複数にチェックして、まとめて OK にもできます。赤い確認事項がある注文は、直すまで OK できません。
  5. 直すもの：
    • 出荷予定日：一覧の日付欄、または詳細の「出荷予定日」で変えます（未確認・OK済のとき）。元の自動の日付に戻すボタンもあります。
    • 社内メモ：詳細の「社内メモ」に書き足します（例：ブルー入荷待ち）。基本の「花岡EC」に続けて SMILE の社内メモに入ります。
    • 納品先（名前・住所・郵便番号・電話）：注文の詳細の「納品先を直す」で直します（未確認のときだけ）。押しただけでは保存されません。直したら「内容を確認する」→ 変更前と変更後が並ぶ確認の画面で「この内容で保存する」を押したときだけ保存されます。間違えたら、項目ごとの「この項目を元に戻す」、または「すべて Shopify の値に戻す」で戻せます。郵便番号から住所を確認するボタンもあります（郵便番号だけを外部の郵便番号検索 zipcloud に送ります。住所は自動では入りません）。直した内容は SharedMasters の _ec_edits に置かれ、誰の画面にも同じ内容で出ます。履歴には「誰がいつどの項目を直したか」だけが残ります（値は残りません）。
    • 品目の対応：「対応表」にない商品は、「対応表・設定」タブで品目を決めます。
  6. SMILE に取り込まない注文：返金対応・別経路で処理済み・テスト注文などは、「対象外」を押して、理由を入れて外します（未確認・要確認の注文）。外した注文は「対象外」の絞り込みに移り、「未確認に戻す」で戻せます。理由に、お客様の名前・住所・電話は書かないでください。
  7. 取り込む（管理者）：画面の下の「SMILEに取り込む」を押すと、OK 済みの注文を専用機が SMILE に取り込みます。
  8. 確認OK（管理者）：取込のあと、SMILE の値が期待どおりなら「確認待ち」になります。確認して「確認OK」で「起票済み」です。
取込の前に、右上の「SMILEの最新を取り込む」で SMILE の最新を読んでおくと、すでに入っている注文を見落としません。

⑥ 注文の詳細：Shopify と SMILE の見比べ

注文をクリックすると右に開きます。左が Shopify の注文、右が SMILE に入る内容です。

ShopifySMILE（予定）
納品先名山田 太郎山田 太郎様
電話+81901234567090-1234-5678
Shopify の注文（青）SMILE（緑）違う項目（黄色）
  • 納品先名・荷受け人・郵便番号・住所・電話・金額が違うと、黄色で強調されます。住所の誤り（都道府県など）に気づけます。名前の末尾の「様」と、電話の「+81」と「0」の違いは、違いとして扱いません。
  • 商品は、Shopify の商品名が、対応表で SMILE の品目に変わります（商品名は違って当然なので強調しません）。
  • 取込前は、右が「SMILE に入る予定の内容」。取込後（SMILE に伝票がある）は、右が「SMILE の実際の値」（確認用ファイルの時点つき）になり、受注№も出ます。「Shopify と何が違って SMILE に入ったか」を、あとからでも見られます。
  • 「確認すること」に、受注の締め・休業日・文字の問題・返金など、注意が出ます。

⑦ 受注の決まりごと（自動で計算されるもの）

項目決まり
受注の締め15時。15時以降の受注は、翌営業日の分として処理します（詳細に「15:00以降の受注：○/○ 分として処理」と出ます）
休業日土日・祝日・年末年始、および Outlook の会社共通予定表（終日の予定で、件名に「休日・休業・祝」を含むもの）。休業日の受注は次の営業日の分として処理します
出荷予定日処理日から 2営業日後（品目ごとに対応表で変えられます）。休業日は避けます。品切れの案内に「次回発送は○月○日以降」とあれば、その日付を使います
社内メモ基本は「花岡EC」。ギフトのときは「花岡EC（ギフティング）」。手で書き足した分は続けて入ります
納品先お届け先が SMILE の納品先マスタにあれば、そのコード。なければ新規として、取込時に専用機が番号を決めます
文字・字数名前・住所は、配送会社の取込で化けやすい文字（機種依存文字・Shift-JIS にない文字）と、字数の上限を確認します。「直してください」と出たものは、取込の前に直す必要があります（⑤の「納品先を直す」で、画面で直せます）
返金・金額返金がある注文は「返金あり」と出ます。SMILE の税抜合計の1.1倍が Shopify の合計とずれると、見比べで黄色になります

⑧ 入金（総務のみ）

  • 「入金（総務）」のタブは、総務の権限のある人にだけ出ます。
  • Shopify の入金（毎時の取得に含まれます）を、入金日 × 得意先でまとめて、SMILE の入金伝票の取込ファイルにします。1行目が振込（通帳の額）、2行目が支払手数料です。
  • 入金額が、取引の合計と一致しているかを見ます。一致しない入金は、取込の前に確認します。

⑨ 履歴（誰がいつ何をしたか）

  • 注文の状態・OK・取込・確認OK・受注№・出荷予定日の変更・社内メモ・対象外は、共有のリスト（SharePoint）に残ります。どの端末から見ても同じ内容です。注文の詳細の下に「履歴」が出ます。
  • お客様の名前・住所・電話は、リストに書きません（注文番号・状態・日時・人・件数・項目名だけ）。
  • リストに接続できないときは、画面の上に表示が出て、この端末にだけ保存します（復旧したら、反映するか確認が出ます）。
  • Shopify の注文の中身そのもの（商品・金額・お届け先）は、履歴には残りません。取得できる直近55日のあいだ、画面で見られます。
  • 納品先を直した場合、取込後は見比べの画面（Shopify の元の値 ↔ SMILE の実際の値）で「どこを変えて入れたか」が分かります。

⑩ 困ったとき

こんなとき確認すること
注文が一覧に出ない上の緑の帯に「Shopify注文 ○件」があるか。「更新」を押す。注文日の絞り込み（「○○以降」）が新しすぎないか。「すべて」を選ぶ。それでも出ないときは、専用機の取得（タスクスケジューラー）を確認
「自動取得が止まっている可能性」と出る専用機のタスク shopify_fetch.py が動いているか、ログ（SharedMasters の _rpa_queue\logs\shopify_fetch.log）を見る。その間は、Shopify から落とした CSV を画面に入れても動きます
名前・住所がおかしい見比べで黄色の項目を確認。Shopify のお届け先そのものが違っていれば、Shopify 側で直してもらう（次の取得で直ります）。急ぎなら「対象外」にして手で入れる
「SMILE取込済」なのに入れていない注文SMILE に同じ注文番号（客先注番）の伝票があるためです。SMILE で確認してください
「要確認」になった注文を開いて、SMILE の値とアプリの期待値の表を見て、SMILE で伝票を確認。再取込は画面からはできません（管理者に連絡）
「他の人が更新しました」と出た他の人が同じ注文を先に操作しています。最新の内容を読み直したので、確認してやり直してください
取込ボタンが押せない・SMILEの最新ボタンが出ないこれらは管理者だけの操作です（管理者の一覧は専用機側で管理）

ここに書いていない動き・おかしな表示を見つけたら、画面を撮って福田さんに知らせてください。
