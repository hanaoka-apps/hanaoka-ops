# 組織計画：等級・在級期間・概算年収

更新日：2026-11-18。人事の実接続・保存・再読込を確認済み。給与の自動取得・拠点の部分失敗は架空データでも検証する。

## 等級

既存の給与画面が「所属（等級）」として使っている人事原本の `所属` を参照する。従業員コードと拠点で照合し、同じ月に複数ある人を自動で決めない。R1-3、R3-2などを取り出し、MGR表記があれば元の表記のまま残す。MGRとRの対応は未確認なので自動変換しない。取り出せない等級や複数の等級が書かれた値は未確認。

現状の案では人事原本の等級を優先し、元の案の将来の変更は残す。他の案は入力済みの等級予定を優先し、等級の登録がない場合は現状を補う。現状から新しい案をコピーしたときは、現在の等級を引き継いだうえで将来の予定を保持する。過去年度に最新の等級を遡って埋めることはしない。導入後に読み込んだ月ごとの等級の控えを残し、翌年度の更新で前年度の等級を変えない。

等級の表示順はMGR1-1→MGR1-2→MGR1-3→MGR2-1→MGR3-1→MGR3-2→同段階のR表記→MGR4-1→MGR4-2→同段階のR表記→MGR5-1。元の等級表記は残し、専任職のR3・R4は対応する段階の中に置く。未確認は最後。等級別平均・絞り込み・一覧の等級順を共通化する。

## 在級期間

- 人事原本の月ごとの記録を、同じ従業員コード・拠点・等級で後ろへ辿る。欠損月や同一月の重複、等級の変更で止める。
- 連続して確認できる最初の月を、昇格日として確定しない。在級期間は「少なくとも（記録で確認できる期間）」と表示する。最初の確認月の月末から、最新月の月末と画面の基準日の早い方までの満月数なので、推測で長く見せない。
- 正確な開始日を確認した場合、行の「在級開始日・試算条件を編集」から登録できる。その日から画面の基準日までの満年・満月を表示する。同じ等級に戻った場合、別の期間の開始日を自動で使い回さない。
- 年だけで登録された等級予定は、日付を4月1日などと推測せず開始日未確認とする。
- 在級期間の基準日は画面で変更できる。初期値は日本時間の今日。年齢は従来どおり表示年度の開始直前の3月31日で、在級期間と区別して明記する。

## 概算年収

依頼者の指定：月額に含めるのは**基本給・役職手当・営業手当と想定残業の追加分**。役員には賞与を加算しない。

- 社員など：`（基本給＋役職手当＋営業手当＋追加残業代）×12＋賞与基準額×年間の賞与月数`
- 役員：`（基本給＋役職手当＋営業手当＋追加残業代）×12`。共通・個別の賞与月数があっても賞与0。
- 役職手当は給与原本の `内訳.役付手当` を使う。賞与基準額の初期値は基本給で、試算条件として変更できる。
- 賞与月数は案ごとに入力し「賞与月数を反映」で確定。個人の試算条件に月数を入れれば個別の想定になる。0か月と未設定を区別する。
- 人員表の区分が役員なら賞与なしを強制する。将来案では「役員の想定（賞与なし）」も指定できる。役員かどうかは等級だけでは判定しない。
- 給与実績は「等級・年収」を開くと自動で読む。「給与を読み直す」で再取得できる。人事と同じ最新月を給与基準月とし、その月と直前2か月の `history/payroll_detail/<年月>_<拠点>.json`（既存画面と同じ本社・工場）を読み、コードと拠点が一件一致した人の金額を表示する。基準月の月給者・役員は年収計算に使い、日給・時給者は明細の金額だけを表示する。
- 日給・時給・給与種別不明、未接続の人は自動で月額に換算しない。月額の想定を入力して試算する。支給合計などがある正規の明細で省略された支給項目は0円とする（既存の支給控除一覧表と同じ）。明細自体の欠損・不正値・未取得は0にしない。
- 現在の給与を将来年度に使う場合は「据え置き」の仮定と明記する。表示年度より後の給与を過去年度の初期値には使わない。
- 深夜・休日・月60時間超の追加割増、その他手当・税・社会保険料・年度途中の在籍月数は含めない。手取りや確定した支給年収ではない。
- 等級別のボタンは平均年収（計算できた人の年収合計÷計算できた人数）を表示し、算出人数/その等級の全人数を併記する。未確認の人は平均の分母に含めず、全員未確認なら「未確認」とする。
- 全体の合計には計算できた人だけを加え、何人分かと未確認の人数を併記する。計算不能の人を0円として合計しない。

## 保存・権限・更新

給与原本はそのまま保存しない。読み込んだ基本給・役付手当は画面のメモリだけに保持し、人事情報が更新されたら自動で再取得する。別の月の金額を混ぜない。一方の拠点の取得に失敗しても、取得できた拠点の金額は使い、未取得の拠点は未確認にする。給与の基準月を必ず表示する。

利用者が保存した試算条件だけを、案ごとの `people[].payPlans[]` に置く（`from`、`basic`、`role`、`bonusBase`、`bonusMonths`、`isOfficer`、`sales`、`overtimeHours`、`workDays`、`overtimeExempt`、各種想定時間）。`from` 年度以降に有効で、後の年度の入力で切り替える。個人の賞与月数が空欄なら案の `payAssumptions.bonusMonths` を使う。その年度の手入力を取り消すと、その前の予定または取得済みの給与に戻る。

確認した在級開始日は `people[].gradeStarts[]`、人事の最新の等級と確認期間は `people[].hrGrade`、導入後に読み込んだ月ごとの等級の控えは `people[].hrGradeHistory[]`、拠点・給与種別・雇用区分は `payrollSite` / `payType` / `employeeKind`。元の人員更新で試算条件と等級予定を消さない。

保存先は既存の3人限定サイトの `org_plan.json`。人員表・給与原本には書き戻さず、ログ・GitHub・資料に実際の氏名や金額を記録しない。見本は常に架空データで保存しない。画面で金額を隠すだけに頼らず、限定サイトと給与サイトの権限を本番で確認する。

## 検証と残る確認

- 自動検証：Rコード・原表記維持、月の連続性、同じコードの重複と拠点、在級期間の下限と確認日、等級予定の保持、基本給＋役付手当、賞与0と未設定、役員の賞与除外、試算条件の年度切替。
- ブラウザのサンプル：等級表示、給与の読み込み、賞与月数の反映、役員の賞与なし、確認開始日からの在級年数を確認。
- 本番の人事・等級・給与種別・明細形式と対象月、SharePoint保存を確認。在級開始日の資料、他の利用者の権限、同時編集は未確認。

MVVに沿っているか：人の成長と将来の組織案を、費用の見通しとともに考えられる。花岡車輌らしいか：維持する手間を減らし、根拠と未確認事項を見ながら使える構成とする。

## 営業手当・残業の試算（2026-11-18追加）

依頼者が確認した会社の試算ルールを使う。法的な賃金判定や確定給与計算には使わない。

- 年間休日の初期値121日。年度の4/1〜翌3/31の日数から引く（2026年度244日、2027年度245日）。1日の所定時間は7時間55分。月平均所定時間＝年間所定日数×475分÷60÷12。
- 時間単価＝（基本給＋役付手当）÷月平均所定時間。単価は途中で丸めず、各支給額の1円未満を切り上げる。
- 通常残業代＝単価×1.25×通常残業時間。営業手当対象者の通常分の追加＝MAX（0、通常残業代−営業手当）。20時間を機械的に引かず金額差で計算する。
- 所定時間内の深夜割増＝単価×0.25×深夜時間、深夜残業＝単価×1.50×深夜残業時間、法定休日＝単価×1.35×休日時間、法定休日深夜＝単価×1.60×休日深夜時間。それぞれを追加分に加算する。通常・深夜残業・休日の時間は重複入力しない。
- 役員、R3以上、MGR3以上、専門MGR3以上は残業代0。個別の対象ありの入力でも上書きしない。等級未確認の人の対象区分は推測せず、個別の対象を確認できるようにする。
- 想定時間は案の `payAssumptions.overtimeHours`、`nightHours`、`nightOvertimeHours`、`holidayHours`、`holidayNightHours`。通常残業は未入力を0とみなさず、深夜・休日は初期値0。個別の `payPlans[]` の時間を優先し、空欄は案の値。年間休日は `annualHolidays`、個別所定日数を確認した場合は `payPlans[].workDays` で変更できる。
- 営業手当は原本の `内訳.営業手当`。月額と年収に含める。支給額が正なら20時間分を含むと表示する。営業手当÷20で単価を推定しない。明細から残業代を割り戻した単価も採用しない。
- 直近3暦月の `勤怠_普通残業` を平均し、確認月数/3と期間を併記する。明細が1件で値を確認できる月のみ使う。未取得・重複は0にしない。深夜・休日を含む総残業とは区別する。
- 基本給は支給明細の実績であり、契約上の満額とは断定しない。支給実績／想定、給与区分と基準月を明示する。低い金額を過去最高額や日数比率で勝手に増額しない。満額の契約基本給は原本に項目がなく、別途確認が必要。
- 原本の最新月が2026-10であることをファイル一覧・給与人事・給与集計で確認。11月データは未登録。実額と氏名は記録しない。
- 原本の値を手入力欄に自動転記して保存しない。空欄の金額は原本更新に従う。時給・日給者は基本給の月額想定を入力するまでは年収を計算しない。
