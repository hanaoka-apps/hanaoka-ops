# HANAOKA LINK「ニュース」のリスト（SharePoint）

置き場はほかの LINK のリストと同じサイト（/sites/hanaoka-link）です。
手で作る場合は、下の表のとおりに列を作ってください。
nippo-board の `provision/Provision-Link.ps1 -Apply` を流すと、この2つのリストと、タグの初期値を自動で作れます（何度流しても同じ状態になります）。

アプリは、リストが見つからないときは「ニュースの置き場（LINK_共有）がまだありません」と表示し、日報・お知らせはそのまま使えます。

## LINK_共有（ニュース本体）

社員全員が読み書きできます。書き換え・削除は「自分が作った行だけ」にします（日報と同じ設定）。

| 列名（内部名） | 種類 | 備考 |
|---|---|---|
| Title | 1行テキスト | タイトル（必須） |
| Body | 複数行テキスト（書式なし） | 本文 |
| Tags | 1行テキスト | 内容タグ。1〜3個。`;受注速報;展示会・イベント;` のように前後を `;` で囲んで保存 |
| Products | 1行テキスト | 製品タグ。`;RIDE;KAKU;` のように前後を `;` で囲んで保存（無いときは空欄） |
| Mentions | 複数行テキスト（書式なし） | 宛先の人のメールアドレス（UPN）を JSON の配列で。例：`["taro@…","hanako@…"]` |
| AuthorUPN | 1行テキスト | 投稿した人のメールアドレス（UPN） |
| Files | 複数行テキスト（書式なし） | 添付。日報と同じ形（JSON） |

- 「作成日時」（Created）に索引を付けてください（新しい順に読むため。5,000件を超えても読めるように）。
- 添付は、ライブラリ LINK_添付 の `全社/ニュース/年-月/` に入ります（フォルダは最初の投稿で自動でできます）。
- スタンプ・コメント・既読は、日報と同じ LINK_反応 に入ります。対象（Target）は `news:番号` です（日報は `post:番号`、お知らせは `notice:番号`）。

## LINK_タグ（タグの一覧）

社員全員が読めます。書けるのは HL-アプリ管理者 だけです（LINK_設定 と同じ設定）。

| 列名（内部名） | 種類 | 備考 |
|---|---|---|
| Title | 1行テキスト | タグ名（`#` は付けない） |
| Kind | 1行テキスト | `content`（内容）か `product`（製品） |
| Sort | 数値 | 並び順（小さいほうが前） |
| Active | はい/いいえ | 「いいえ」にしたタグは選べなくなるが、過去の投稿には表示する |
| OldNames | 1行テキスト | 前の名前。`;` 区切り。アプリでタグの名前を変えたときに自動で入る（手で入れなくてよい） |

`OldNames` は指示書に無かった列です。タグの名前を変えても、前の名前で投稿されたニュースが新しい名前のタグで探せるように足しました。
この列が無くても動きますが、そのときは名前を変えると、前の投稿はそのタグで出なくなります。

### タグの初期値

| Kind | Title（Sort の順） |
|---|---|
| content | 受注速報 / 導入事例 / 展示会・イベント / メディア掲載 / 市場・競合 / 補助金 / 外来書類 / 基幹システム / 社内報 / その他 |
| product | RIDE / KAKU / フラットカート / レベルカート / 電動台車(ML) / トレーラー |

Sort は 10, 20, 30 … のように間を空けて入れておくと、あとで間に足しやすくなります。Active はすべて「はい」。

## お知らせの宛先（LINK_お知らせ の Audience 列）

選択肢に `honsha` を足してください（「本社のみ」。大阪・名古屋の営業所の人を除く）。
今までの `hq` は「本社・大阪・名古屋」という表示に変わります（見られる人は今までと同じです）。

| 値 | 表示 | 届く人 |
|---|---|---|
| all | 全社宛 | 全員 |
| exec | 幹部のみ | HL-幹部 |
| honsha | 本社のみ | 勤務地が「本社」で、部署欄が大阪・名古屋ではない人 |
| hq | 本社・大阪・名古屋 | 勤務地が「本社」の人と、部署欄が大阪・名古屋の人 |
| factory | 工場のみ | 勤務地が「工場」の人 |
