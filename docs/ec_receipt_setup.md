# 領収証（EC）を使い始める手順

閲覧画面（`ec_viewer.html`）とEC売上（`ec_sales.html`）の「領収証を発行」は、準備ができるまで隠れています（`ec_sales_config.json` の `receipt.enabled` が `false`）。
次の順に準備します。★は、福田さん（管理者）の作業です。

## 0. 先に決めておくこと
- ★ **経理に確認**：電子（PDF）の領収証でよいか、収入印紙が要る金額かどうか（アプリは法的な判断をしません）。
  - 収入印紙が必要な金額は、電子ではなく、印刷して印紙を貼って郵送する運用です。**基準の金額**（税込で、いくら以上か）を経理に確認して、`ec_sales_config.json` の `receipt.stampNoticeAmount` に入れます（円の数字。空＝`null` のままなら、何も出ません）。
  - 入れると、基準以上の金額の発行画面に注意が出て、印刷に「収入印紙 貼付欄」が付きます（発行後の画面の「紙で出す」のチェックで外せます）。
- ★ いまの領収証の**書式の見本**（Excel / Word）を渡す。社名・住所・登録番号・社印・但し書き・宛名の位置をそろえます（個人情報は伏せてください）。

## 1. テスト用のリストを作る
管理者（SharePoint のサイト管理者）が、PowerShell 7 で次を実行します（何度やっても安全。すでにあるリストは壊しません）。

```bash
pwsh -File scripts/create_ec_lists.ps1 -Offline
pwsh -File scripts/create_ec_lists.ps1 -ReceiptList EC_Receipt_Test -Apply
```
- 1行目：何を作るかを見るだけ（サインインも書き込みもしません）。
- 2行目：テスト用のリスト `EC_Receipt_Test` を作ります。EC_Log には、選択肢「領収証発行／再発行／取消」が足されます。
- 作る場所は、EC売上の履歴（EC_Order・EC_Log）と同じサイトです。

## 2. 権限を絞る（作ったリストごとに）
宛名（お客様の名前・会社名）と金額が入るので、サイト全員には見せません。
リスト右上の「設定」→「リストの設定」→「このリストに対するアクセス許可」→「アクセス許可の継承を停止」。
そのうえで、**営業と EC 担当と管理者**だけを、「編集」（読み書き）にします。
※ 営業が読めないと、閲覧画面にボタンも札も出ません（エラーは出ません）。

## 3. 設定ファイルと社印を SharedMasters に置く
`receipt_settings.json`（実際の会社の値に書き換える）と、社印の画像（PNG 推奨・背景は透明・正方形に近いもの）を、SharedMasters の直下に置きます。

```json
{
  "company": { "name": "サンプル商事株式会社", "zip": "000-0000", "address": "サンプル県サンプル市サンプル町0-0-0", "tel": "000-000-0000", "registrationNo": "T0000000000000" },
  "stampFile": "receipt_stamp.png",
  "footerNote": ""
}
```
（上は架空の見本です。`stampFile` と `footerNote` は、なくてもかまいません。）
**実際の社名・住所・登録番号・社印の画像は、GitHub（リポジトリ）には入れません。**

## 4. テスト用のリストで確かめる（PR）
`ec_sales_config.json` の `receipt` を次のようにして PR を出し、マージします。

```json
"enabled": true,
"list": "EC_Receipt_Test"
```
確かめること（営業の担当者と、できれば読めない人でも）：
1. 入金済みの注文に「領収証を発行」が出る／入金待ち・キャンセルには出ない。
2. 初めて発行を押したときに、書き込みの権限の同意の画面が出る（「承諾」）。
3. 発行 → 印刷／PDF に保存 → 見た目（書式・社印）。
4. 再発行・取消・宛名や金額を変えての出し直し。「領収証：発行済み」の札と、閲覧画面での「領収証」検索。
5. 閲覧画面とEC売上の**どちらから出しても同じ記録**になる。
6. リストを読めない人には、ボタンも札も出ない。

※ テストでも、EC_Log（履歴）には、「領収証発行 R-…」のような行（番号だけ）が残ります。

## 5. 本番に切り替える
1. 本番用のリストを作る：`pwsh -File scripts/create_ec_lists.ps1 -Apply`（`EC_Receipt` ができます）→ 手順2の権限を絞る。
2. `ec_sales_config.json` の `receipt.list` を `"EC_Receipt"` に戻す PR を出して、マージする（`enabled` は `true` のまま）。
3. テスト用のリスト `EC_Receipt_Test` は、確認ができたら削除する。

## うまくいかないとき
- ボタンが出ない：`receipt.enabled`／リストの権限（その人が読めるか）／入金済みの注文か、を確かめます。
- 「領収証の設定がありません」：SharedMasters の `receipt_settings.json` が、ないか、読めないか、項目が足りません。
- 「権限がありません」：その人が、リストに書き込めません（手順2）。
