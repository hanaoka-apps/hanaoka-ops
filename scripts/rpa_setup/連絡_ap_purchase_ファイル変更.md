## 2. やってほしいこと（ページ側）

### (1) `smile.rules` の `rpa.files` を新しいファイル名に

ページは `SMR.rpa.files` に書かれた名前のファイルを SharedMasters から読みます（`rpaWaitFiles` / `smLoad`）。値を次の名前に変えてください。キー名は今のままで構いません（読み込み後の種類は見出しで判定しているため）。

```json
"rpa": {
  "job": "ap_purchase",
  "files": {
    "payList":  "支払一覧表.csv",
    "p9055":    "月次支払明細表.csv",
    "receipts": "月次受入リスト.csv",
    "master":   "仕入先マスタ.csv"
  }
}
```

（`Provision-SmileAP.ps1 -Apply -ResetRules` で入れているなら、スクリプト側の既定値も合わせて変えてください。今のキー名が違う場合は、今のキー名のまま値だけ変えてください。）

### (2) 支払一覧表のタブ区切りを読めるように

SMILE の支払一覧表はテキスト出力ができないため、RPA は「画面出力」→ メニューの「コピー(P)」でクリップボードに入った内容を、**そのまま** `支払一覧表.csv` に保存します（Excel は通さない。Excel 経由だと Shift_JIS になり、仕入先コードの先頭の0も落ちたため）。
中身は **UTF-8（BOM付き）・タブ区切り・ダブルクォートなし**。数値は桁区切りのカンマ付き（例 `1,129,649`）。仕入先コードは先頭に空白が付く（例 ` 001103`）。

今の `readRows`（`ap_smile_import.html`）は CSV を `S.parseCSV`（カンマ区切り）で読むので、このファイルは1行が1列になり `kindOf` で判定できません。タブ区切りを見分けて読むようにしてください。例：

```js
// SMILE の画面出力のコピー（支払一覧表）はタブ区切り・クォートなし。数値にカンマが入るのでカンマでは割らない
const head=text.slice(0,2000);
if(head.includes('\t')&&!/^\uFEFF?"/m.test(head))return text.replace(/^\uFEFF/,'').split(/\r?\n/).map(l=>l.split('\t'));
return S.parseCSV(text);
```

（SMILE のテキスト出力の CSV は見出しも値もダブルクォートで囲まれているので、「タブがあってクォートで始まる行がない」でタブ区切りと見分けられる。）

`readPayList` は、このコピーの形（1行目「支払一覧表」、2行目「2026年 9月30日締 今回支払分」、3行目「今回支払／今回仕入額」の見出し、4行目の見出し行、最後の「【総合計】」行、コードの先頭の空白）を、そのまま扱えることを確認済みです（見出し行の「コード」が2回出るが、`colIndex` は最初の列を使う。`g()` が前後の空白を取る）。
