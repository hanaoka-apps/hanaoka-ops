## 1. 何のためのジョブか

HUB の「会社の現在地」の **生産・仕入** に、「🔄 更新をリクエスト」ボタンを付けました（管理者のみ表示。営業の「再集計をリクエスト」と同じ）。
押すと `fujin_source` が依頼され、RPA専用機が SMILE から次の2つを **出し直します**。

| ファイル | 使われ方 |
|---|---|
| `受入明細出力.csv` | FUJIN の日別仕入金額（HUB の仕入カード） |
| `製造実績明細出力.csv` | FUJIN の完成実績（HUB の生産タイル） |

## 2. 反映のしかた（RPA専用機にGitHubのトークンは置きません）

出力したCSVは、**FUJIN の日次ビルド（GitHub Actions・1日2回）が次に動いたときに**反映されます。
ビルドを今すぐ起動する処理（`after`）は付けていません。トークンを専用機に置かないというユーザーの判断です。
そのため、このジョブの完了は「SMILE出力が終わった」ことだけを意味します（HUB も、そう表示します）。

## 3. 作ってほしいPADフロー

- フロー名：**`Smile_生産仕入明細出力`**（`rpa_jobs.json` の `fujin_source.flow` と同じ名前）
- 作り方：`Smile_日報用マスタ出力` を複製して、5行目「テキストの分割」の画面名一覧を、上の2ファイルを出す画面名にする
  （`customer_master` の `Smile_得意先マスタ出力` と同じやり方。手順は `新PC引き継ぎ.md` の「2. PADフロー」）
- 出力先：SharedMasters 直下に**上書き保存**、ファイル名は固定
- **条件・列名・列の順序は、SMILE標準の定時処理「マスタ出力（毎日0時台）」が今出しているものと同じにする**
  （2つとも毎日 0:06 に出力されています。FUJIN の取り込み処理は今の列構成を前提にしているので、変えると集計が止まります）
- 出力画面名が分からないときは、定時処理「マスタ出力」の設定で、`受入明細出力.csv` と `製造実績明細出力.csv` を出している画面を確認してください

## 4. 動作確認

1. HUB（管理者でサインイン）の「生産・仕入」で「🔄 更新をリクエスト」を押す
2. `_rpa_queue/pending` に依頼が置かれ、専用機が `Smile_生産仕入明細出力` を実行する
3. 2つのCSVの更新時刻が新しくなれば完了。HUB には「SMILEの出力が完了しました。次の自動ビルドで反映されます」と出る
4. 次の FUJIN 日次ビルドのあと、HUB の生産タイル・仕入カードの「データ更新 ○/○ ○:○（○/○ まで）」が新しくなる
