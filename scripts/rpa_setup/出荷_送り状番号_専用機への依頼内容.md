# 出荷・配送の検索（ship_search.html）：専用機への依頼内容

出荷した荷物の送り状番号を、受注・得意先・品目から探せる画面（`ship_search.html`）のために、専用機にお願いしたいことです。
画面は読むだけです。データは、専用機が `SharedMasters` に置くファイルから作ります。

## 1. 全体の流れ

```
SMILE ── 出荷明細出力.txt・受注明細出力.csv（夜間の全件出力）──────────────┐
西濃運輸  ─ Webからダウンロード（別の専用機・平日の毎時）→ _ship_inbox\seino\ ──┤
第一貨物  ─ Webからダウンロード（別の専用機・平日の毎時）→ _ship_inbox\daiichi\ ─┼→ build_ship_index.py → ship_index.json → 画面
トナミ運輸 ─ 出荷した日に人が「送信」→ メール → Power Automate → _ship_inbox\tonami\ → ship_unzip.py（解凍）┘
```

- つなぎのキーは、SMILE の出荷明細の **売上№** です。運送会社に渡す取込データの「管理番号」（西濃・第一貨物）と「指定No記号」（トナミ）が、売上№です（3社で、実データを突き合わせて確認済み）。出荷№（別の列）は使いません。
- 運送会社ごとの読み方（フォルダ・列・追跡リンクの型）は、リポジトリの **`ship_config.json`** に書いてあります。画面も `build_ship_index.py` も、ここを読みます。
- CSV には、お届け先の名前・住所・電話が入っています。**`SharedMasters`（社内限定）の外には出さない**でください。画面用の `ship_index.json` には、電話・住所を入れていません。

## 2. 別の専用機（西濃・第一貨物のダウンロード）への依頼

| 項目 | 内容 |
|---|---|
| 置き場所 | `SharedMasters\_ship_inbox\seino\`（西濃運輸）、`SharedMasters\_ship_inbox\daiichi\`（第一貨物） |
| ファイル名 | ダウンロードした名前のまま（日時が入っている）。**上書きしない**。毎回、新しいファイルとして置く（中身が同じでも） |
| 期間 | 毎回、**直近45日**ぶんの出荷を出す（前の回が抜けても、次の回で補える） |
| 頻度 | 平日の 8:00〜18:00 の毎時0分 |
| 形式 | **変えない**（Shift_JIS のまま。第一貨物は見出しなし、西濃は見出しあり）。列は今のままでよい |
| 失敗したとき | 前のファイルはそのまま残す。ログは専用機側に残す |
| 古いファイル | 置いてから14日たったものを消す（`SharedMasters` の中の `seino`・`daiichi` のフォルダだけ） |

- ログイン情報（ID・パスワード）は、**その専用機の環境変数かパスワード管理だけ**に置いてください。リポジトリ・設定ファイル・ログ・チャット（Claude や Teams）には書かないでください。
- 画面は、フォルダの**最新のファイルの時刻**を見て、「平日で30時間以上、新しいファイルが届いていない」ときに警告を出します。ダウンロードが止まったら気づけるようにするためです。
- 今ある見本：西濃＝`0485415711…SHUKKADL.csv`（見出しあり45列）、第一貨物＝`ID…download.csv`（見出しなし45列）。

### 列の読み方（`ship_config.json` の `carriers`）

| 会社 | 見出し | 売上№ | 送り状番号 | 出荷日 | 個数 | 重量 |
|---|---|---|---|---|---|---|
| 西濃運輸 | あり | `管理番号`（先頭の 0 は外して比べる。空は読み飛ばす） | `お問合せ番号`（10桁） | `出荷予定日` | `個数` | `重量（Ｋ)` |
| 第一貨物 | なし | 43列目（位置 42） | 1列目（位置 0）11桁 | 36列目（位置 35） | 位置 36 | 位置 37 |
| トナミ運輸 | あり | `指定No記号` | `送り状No`（10桁） | `出荷日` | `個数` | `重量` |

列が変わったときは、`ship_config.json` を直せば足ります（コードは変えません）。

## 3. トナミ運輸：メールで届く ZIP を受け取って解凍する

トナミのイージープロWebには、ファイルをダウンロードする画面がありません。代わりに、**出荷指示一覧の「送信」ボタン**で、検索結果を、メールの添付ファイル（パスワード付き ZIP）で受け取れます（イージープロWeb 取扱説明書 12・45ページ）。

### 3-1. 最初に一度だけ（福田さん・業務センター）

1. イージープロWeb → 設定 → **ユーザ設定** → 「メール送信先(TO)」に、**受信用の共有メールボックス**を入れて「登録」。
   - 受信用の共有メールボックスは、ふるさと納税の注文メールを Power Automate が読んでいるものと**同じにしてもよい**（フローを分けて、送信元・件名・ZIP の名前で見分ける）。決めるのは福田さんです。
   - まずは、**試しに福田さん自身のアドレス**で、メールが届くことと中身を確認してから、本番の宛先に変えます（済み：中身は確認済み）。
2. 「送信」ボタンは、ユーザ設定にメールアドレスを登録すると、**出荷指示一覧の画面の右下**に出ます。

### 3-2. 出荷した日の操作（業務センター。月に7件ほど）

1. イージープロWeb → **出荷指示一覧** → 確定状況「全て」、日付を**直近の出荷が入る範囲**（例：その月の1日〜今日）にして「検索」。
2. 右下の **「送信」** を押す。
   - 忘れても、次に押せば、直近70日分が送られます（トナミ側の保存期間が70日です）。
   - 検索結果の全件が1つの ZIP に入ります。同じ出荷が何度入っていても、画面側で売上№ごとに新しいものを使うので、問題ありません。

### 3-3. Power Automate（クラウドフロー）

ふるさと納税の「メール受信_ふるさと納税」と同じ作りです。

| 項目 | 内容 |
|---|---|
| トリガー | 「新しいメールが届いたとき（V3）」。受信用の共有メールボックス |
| 条件 | **添付あり**、送信元・件名はトナミ（イージープロWeb）のメールに合わせる。添付ファイル名が `SYUKKA_LIST_` で始まる ZIP だけを対象にする |
| 保存先 | `SharedMasters\_ship_inbox\tonami\` に、**添付のファイル名のまま**（`SYUKKA_LIST_yyyyMMdd_HHmmss.zip`）保存。同じ名前が既にあれば上書きでよい |
| ZIP 以外 | 何もしない |

### 3-4. 専用機：`scripts/ship_unzip.py`（タスクスケジューラー・5分おき）

- `ship_config.json` の `carriers.<会社>.zip` がある会社（トナミ）の ZIP を解凍して、CSV を `_ship_inbox\tonami\csv\<ZIPの名前>\` に置きます。ZIP は `done\`（失敗は `failed\`）へ移します。
- パスワードは、**イージープロWebのユーザーID**で、固定です。専用機の環境変数 **`SHIP_TONAMI_ZIP_PASSWORD`** にだけ入れてください（環境変数の「名前」は `ship_config.json` にありますが、値はどこにも書きません。**コード・設定・ログ・チャットに書かない**）。
- 必要な環境変数：`SHARED_MASTERS_DIR`（同期済みの SharedMasters のパス）、`SHIP_TONAMI_ZIP_PASSWORD`。
- 実行：`python scripts\ship_unzip.py`（毎回リポジトリの最新を取得して実行する形は、`furusato_unzip.py` と同じでよい）。`pip install pyzipper` が入っていれば AES の ZIP も読めます（`scripts/requirements.txt`）。
- ログ：`SharedMasters\_rpa_queue\logs\ship_unzip.log`（パスワード・CSV の中身は出さない）。処理済みの ZIP は14日、解凍した CSV は200日で消します。
- **ふるさと納税の `furusato_unzip.py` とは別のタスクにしてください**（どちらかが止まっても、もう一方に影響しないように）。2台で同じ ZIP を取り合わないよう、**1台だけ**で動かしてください。

## 4. 検索用ファイル `ship_index.json` を作る（RPA専用機 USER02）

`scripts/rpa_jobs.json` に、ジョブ **`ship_index`**（`after: build_ship_index`）と、定時実行（`schedules`）を追加しました。常駐スクリプト（`rpa_queue_worker.ps1`）を **`git pull` して、再起動**すると有効になります（`rpa_queue_worker.ps1` に `build_ship_index` を足したため）。

| 時刻 | 目的 |
|---|---|
| 1:20 | 夜間の SMILE 出力（出荷明細・受注明細）のあと |
| 8:20〜18:20 の毎時20分 | 西濃・第一貨物のCSVが毎時0分に置かれる、そのあと（OneDrive の同期を待つ） |

- 作るもの：`SharedMasters\ship_index.json`（約3MB。置き換えは一瞬で、失敗したら前回のファイルが残ります）。
- 入力：`出荷明細出力.txt`、`受注明細出力.csv`（SharedMasters 直下）、`_ship_inbox` の運送会社の CSV。
- 約5秒で終わります（実データ：直近180日の出荷6,254件・受注明細約5万行）。ログは件数だけで、お客様の名前は出しません。
- 手で動かすとき：

```powershell
$env:SHARED_MASTERS_DIR = '<SharedMasters のパス>'
python scripts\build_ship_index.py --config ship_config.json
```

### 4-1. SMILE の夜間出力に `出荷明細出力.txt` を足してください（要相談）

今の `出荷明細出力.txt` は、福田さんが手で置いたものです。**SMILE の夜間の全件出力（0時台）に「出荷明細出力」を加えて、同じ名前で上書きする**と、画面が毎朝、前日までの出荷に追いつきます。

- 形式：UTF-8（BOM付き）、カンマ区切り、見出しあり、約200列（今のものと同じ）。見出しの名前で列を探すので、列の順番が変わっても動きます。
- 必要な見出し：`伝票日付`・`売上№`・`出荷№`・`得意先コード`・`得意先名１`・`納品先コード`・`納品先名`・`担当者名`・`品目コード`・`品目名`・`数量`・`受注№`・`配送指定日`・`配達指定名`・`運送業者利用区分`・`客先注番`・`明細区分名`・`取引区分名`。
- 夜間出力に足せない間は、手で置いたファイルのままでも動きますが、新しい出荷は、置き直すまで画面に出ません。**当日の出荷が画面に出るのは、翌朝の出力のあとです**（運送会社のデータが先に届いた送り状は、画面の下の「SMILE の出荷明細に見つからない送り状」に出ます）。

- トナミのメールを受ける**共有メールボックス**と、送信元・件名の見分け方。
- 将来：画面から「今すぐ更新」を依頼する（ボタン）。まずは定時だけで始め、必要になったら追加します。
