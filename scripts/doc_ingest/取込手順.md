# 書類取込エージェント 手順

福田さんのPCで定期実行される Claude が、この手順に従って
スキャンされた書類を読み、書類管理システムの台帳に流し込む。

対応する画面は `doc_management.html`（書類管理システム）。

---

## 全体の流れ

```
  複合機でスキャン
        ↓
  <スキャンフォルダ>\*.pdf   ← 場所は scan_dir.local に書く（.gitignore済み）
        ↓  ← ここから下がこの手順
  ① 新着を検出          new_scans.sh
  ② PDFを読む           1本ずつ中身を読み取る
  ③ 原本をコピー        書類管理/原本/YYYY/
  ④ 取込票を書く        書類管理/_取込待ち/YYYYMMDD_HHMM.json
        ↓  ← OneDriveの同期がSharePointへ運ぶ
  ⑤ 福田さんが画面を開く → 台帳に登録される（アプリが自動でやる）
  ⑥ 福田さんが内容を確認・修正
```

### この作りにした理由

**エージェントに書き込み権限を持たせない。**
台帳に行を作るのは、常にサインインした福田さんの権限。
エージェントは同期フォルダにファイルを置くだけなので、
このPCに認証情報を一切置かずに済む。

**原本には絶対に触らない。**
スキャンフォルダのファイルは移動も削除もリネームもしない。
コピーするだけ。アプリ上の「対象外」も台帳の行を隠すだけで、
書類そのものは消えない。

---

## ① 新着を検出

```bash
bash scripts/doc_ingest/new_scans.sh
```

スキャンフォルダにあって `書類管理/原本/` に無いPDFを出す。
状態ファイルは持たない（ズレる・壊れる・消えるため）。
「原本フォルダに置いてあるか」だけで判定している。

初回は過去分も全部出る。1回で全部やらず、**1回あたり10〜20件まで**にして
何回かに分ける。古いものから順に処理する。

---

## ② PDFを読む

スキャン画像なのでテキスト層は無い。**Readツールで直接PDFを開いて目で読む。**
`pdftotext` は空を返すので使わない。

読みながら、次を拾う。

### 必ず拾うもの

| 項目 | 補足 |
|---|---|
| タイトル | 「誰から・何の書類か」が一目で分かる日本語。ファイル名は使わない |
| 差出元 | 会社名。支店・部署まで分かれば入れる |
| 担当・連絡先 | 担当者名・TEL・FAX |
| 書類種別 | 案内／契約書／明細表／通知／請求書／証明書／申請書／報告書 など |
| カテゴリ | 下の一覧から選ぶ |
| 文書日付 | 書類に書かれた日付。和暦は西暦に直す（令和8年＝2026年） |
| 受領日 | スキャン日（ファイルの更新日時） |
| 金額 | 税込の総額。**「その書類の主たる金額」が1つに定まらないなら空にする** |
| 識別番号 | 契約No・証券番号・取引番号・登録番号・車台番号など。**つながりの手がかりになるので漏らさない** |
| 要約 | 3〜6文。何の書類で、何が書いてあり、何が起きるか |
| 要確認ポイント | 期限・読み取れなかった箇所・違和感 |
| 全文テキスト | 読み取れた文字を可能な限り。**検索はここに当たる** |

### カテゴリ

`金融・銀行` / `リース・車両` / `購買・契約` / `保険` / `税務` /
`人事・労務` / `社内稟議` / `その他`

足りなければ新しいものを作ってよい。列は固定していない。

### そのほか拾った項目

`extra` に好きなキーで入れる。**台帳の列は増やさなくてよい。**
書類は種類が読めないので、固定の枠に押し込めない。
契約なら契約条件、車なら車台番号と走行距離、保険なら補償内容、
その書類で意味のある項目をそのまま入れる。

## ③ タスクにするかどうか

**「読んだ人が何かしないと不利益が出るか」** で決める。
出るならタスク、出ないなら保管のみ。

タスクにする例:

- 返送・回答が要る（承諾書、アンケート、確認依頼）
- 期日までに判断が要る（満期、契約更新、リース満了）
- 支払予定に載せる必要がある（契約書・請求書）
- 手続きしないと権利が消える（**証書の返却請求など、本文の末尾に紛れていることが多い**）

タスクにしない例:

- 定期的に届く残高・実績の明細（保管のみ）
- 既に引落・振替が済んでいるもの
- 過去分の控え

期限は**書類に書かれた日付をそのまま使う**。
「本状受取後1ヶ月以内」のような相対期限は、受領日から計算したうえで
**要確認ポイントに「実際の到着日が不明」と必ず書く**。
勝手に確定した日付だけ置いていくと、後で誰も疑わなくなる。

`task.why`（なぜタスクにしたか）を必ず書く。
福田さんが「これは要らない」と判断するための材料になる。

---

## ④ 信頼度

| 値 | どういうとき |
|---|---|
| `高` | 主要項目が全部くっきり読めた |
| `中` | 読めたが、解釈に迷う箇所がある（金額がどれを指すか等） |
| `低` | **読み取れなかった項目がある／差出元が特定できない／期限が推定** |

**迷ったら低に倒す。** 高くしておくと誰も見直さない。
低いものは画面上で赤く出て、福田さんの確認が入る。

## ⑤ 原本をコピーして取込票を書く

原本:

```
書類管理/原本/<文書日付の年>/<元のファイル名のまま>.pdf
```

ファイル名は変えない。スキャンフォルダの原本と突き合わせられなくなる。

取込票:

```
書類管理/_取込待ち/<YYYYMMDD_HHMM>.json
```

複数件を1つの取込票にまとめてよい。形式:

> このリポジトリは**公開**されている（GitHub Pagesで配信）。
> ここに書く例は**必ず架空の値**にすること。実物の契約番号・車両番号・
> 取引先の担当者名や電話番号を書かない。

```json
{
  "generatedAt": "2026-09-16T18:45:00+09:00",
  "agent": "claude-doc-ingest",
  "items": [
    {
      "sourcePath": "<スキャンフォルダのフルパス>\\20260916165758400.pdf",
      "filePath": "書類管理/原本/2026/20260916165758400.pdf",
      "fileName": "20260916165758400.pdf",
      "title":    "リース契約満了のご案内（○○工場 △△車）",
      "category": "リース・車両",
      "sender":   "○○リース株式会社",
      "docDate":  "2026-07-31",
      "received": "2026-09-16",
      "due":      "2026-10-09",
      "amount":   270600,
      "taskStatus": "未着手",
      "data": {
        "docType":       "案内＋契約書",
        "senderContact": "○○支店 営業一課 担当者名 TEL 000-000-0000",
        "confidence":    "高",
        "summary":       "…3〜6文…",
        "checkPoints":   "★満了日 2026年10月9日まで。…",
        "keys":          ["<契約番号>", "<登録番号>", "<車台番号>"],
        "extra":         { "契約番号": "…", "走行距離": "…" },
        "task": {
          "title": "再リース契約承諾書を返送",
          "owner": "総務部",
          "why":   "満了日が2026年10月9日。終了なら当日返車が必要なため。"
        },
        "fullText": "…読み取れた文字を可能な限り…"
      }
    }
  ]
}
```

- 日付は全て `YYYY-MM-DD`。和暦は西暦に直す
- `amount` は数値（カンマ・円マーク無し）。定まらないなら `null`
- タスクが無い書類は `data.task` ごと省く
- `filePath` は `ドキュメント` ライブラリから見た相対パス

書いたらそこで終わり。**台帳への登録はアプリがやる。**

---

## ⑥ つながりについて

取込時に無理に繋げようとしなくてよい。
`keys` をきちんと拾っておけば、**アプリ側が「これ、つながっていませんか？」と
候補を出す**。確定するのは福田さん。

ただし、読んでいて明らかに前の書類の続きだと分かったら、
`checkPoints` に「○月○日の△△と同一案件の可能性が高い」と書いておく。
番号が違っても人は気づける。

---

## やってはいけないこと

- スキャンフォルダの原本を移動・削除・リネームする
- 認証情報をこのPCに保存する
- 読み取れなかった項目を、それらしい値で埋める
  （空にして信頼度を `低` にする。埋めると誰も気づけない）
- 1回の実行で大量に処理して、確認しきれない量を福田さんに渡す
