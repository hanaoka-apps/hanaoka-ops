# 支払決済スケジュールの月次カレンダー登録

総務部が毎月作成する「支払決済スケジュール」(Excel/PDF)のうち、全社に
関係する重要日だけを `company-calendar@hanaoka-corp.co.jp` の共有カレンダー
(会社共通予定表)へ終日予定として登録する、月1回の作業の手順。

## 毎月やること

1. 総務から最新月のファイル(Excel or PDF)を共有してもらう
   (例: `\\192.168.100.150\hanaoka\各部署フォルダ\総務\スケジュール\支払決済スケジュール20XX-20XX.xlsx`、
   または月ごとのPDF `202X10.pdf` など)
2. ファイルの中から、**ラベル付きの色付きバー**(特定の日付のセルに乗っている
   件名)だけを抽出する。「本編」(column: main)と「補足」(column: sub)の
   2種類に分けること(下記「列分けについて」参照)。対象の例:
   - 本編(main): 「10日支払決済」「20日支払決済」「月末支払決済・でんさい」
     「株ハナ月末支払決済」「車輌・株ハナ　給与決済」「総合会議」
     「エンサイド監査」など
   - 補足(sub): 「<10日>支払決済資料 完成」「<20日>支払決済資料 完成」
     「<月末>支払決済資料 工場完成」「<月末>支払決済資料 工場以外完成」
     「<月末>各部提出・確認」「<月末>工場支払決済・確認」
     「<月末>銀行送金・送金内容確認」「<月末>でんさい決済」など
     (締め日の何営業日前、という形で日付が振られている個別の作業ステップ。
     以前は対象外にしていたが、これも必要とのことなので含める)
3. 以下は**対象外**:
   - AM/PM欄の細かい担当者ローテーション(誰が何時に何をするか)
   - 右側の「基本スケジュール」「締め日ルール」説明パネル(生成規則の
     テキストで、日付に紐づくイベントではない。上記2.の「補足」は
     日付グリッド上に実際に配置されているバーのことで、この説明パネルとは別)
   - ReHANAOKA展のような**単発・イレギュラーな行事**(既に別ルートで
     全社スケジュールへ登録済みのため対象外。総務に確認してから対象外と
     判断すること)
4. 抽出した `{date, subject, column}` の配列を用意し、
   `scripts/register_payment_schedule.py` をローカルで実行して登録する(下記)。

## 列分けについて

`company_schedule.html`の一覧表示は「日付／お知らせ／定例・決済／準備・作業」の
4列(表示名)。このスクリプトで登録したイベントにはOutlookのカテゴリで
`column`(main→カテゴリ「定例・決済」、sub→カテゴリ「準備・作業」。画面の
列名と同じ)のタグを付けており、company_schedule.htmlはそのカテゴリを見て
列を振り分けている(以前の名前「総務スケジュール」「総務スケジュール補足」も
当面は同じ列として扱う)。**このスクリプトを経由せず
担当者が手入力した予定(入社案内・ReHANAOKA展など)にはカテゴリが付かない
ため、自動的に「お知らせ」列に入る**(担当者側で何か
設定を変える必要はない)。

## 実行方法(ローカル実行、GitHub Actions は使わない)

日付・件名の抽出さえできれば、あとはこの1コマンドで完結する。GitHub
Actions経由にしていた時期もあったが、月1回・人が確認しながら行う作業には
オーバースペックだったため、ローカル実行に統一した。

```bash
AZURE_TENANT_ID='3933e8a0-c945-4e97-ae67-c82131087cad' \
AZURE_CLIENT_ID='d338d61b-01dc-4c7c-ac6b-aecf7f30d716' \
AZURE_CLIENT_SECRET='<都度発行する。下記参照>' \
EVENTS_JSON='[{"date":"2026-10-06","subject":"総合会議","column":"main"}, {"date":"2026-10-09","subject":"<10日>支払決済資料 完成（担当：幹部）","column":"sub"}, ...]' \
python3 scripts/register_payment_schedule.py
```

`column`を省略すると`"main"`扱いになる。

- `AZURE_TENANT_ID` / `AZURE_CLIENT_ID` は固定値(上記のとおり)。
- `AZURE_CLIENT_SECRET` は保存していない。実行するたびに以下の手順で
  その場で新規発行してもらう(福田さんにお願いする):
  1. Azure Portal → 「花岡車輌 業務アプリ」(appId `d338d61b-...`) →
     左メニュー「証明書とシークレット」
  2. 「新しいクライアント シークレット」→ 有効期限は適当(6ヶ月など)→追加
  3. 一覧に表示される**「値」**の列(シークレットIDではない方)をコピー
     してその場で渡してもらう。ページを離れると二度と表示されないので
     注意。
- 実行すると、既に同じ日付・件名の予定があればスキップされる
  (`完了: 登録N件 / カテゴリ更新N件 / 既存スキップN件` と表示される)。
  重複登録の心配は基本的に無い。既存の予定にカテゴリが付いていない・
  違う場合は作り直さず付け直すので、以前カテゴリ無しで登録した分の
  修正にもそのまま使える。

## 権限まわり(設定済み・変更不要)

- Azure ADの「花岡車輌 業務アプリ」に **Calendars.ReadWrite (アプリケーションの
  許可)** を追加し、管理者の同意を付与済み。
- Exchange Online側で、このアプリが `company-calendar@hanaoka-corp.co.jp`
  **以外**のメールボックスには触れないよう、Application Access Policyで
  制限済み(メール有効セキュリティグループ `AppScope-CompanyCalendar` 経由)。
  他の人のカレンダーには影響しない。

## 表示側

登録したイベントは以下にそのまま反映される(コード変更不要):

- HUB(`hanaoka_hub.html`)の「お知らせ」欄・サイドバーの「お知らせ」リンク
- `company_schedule.html` (会社共通予定表だけを月カレンダー形式で表示する
  軽量ページ。「お知らせ一覧へ」のリンク先)
- `staff_schedule.html` (個人の予定と並べて週単位で見る場合)
